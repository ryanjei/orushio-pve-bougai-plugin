# v1受入基準・テスト

## 1. 判定方法

- `必須`が1件でも不合格なら、そのPhaseまたはv1は未受入。
- `推奨`は既知制限として記録し、配信運用に重大影響がなければ後続へ回せる。
- 自動テストで確認できるものは自動化する。
- 実Paper確認は各Phaseの節目だけ行う。

## 2. Phase 1受入

### 必須

- Gradle Wrapperからビルドとテストが成功する。
- Paperがプラグインをロードし、重大エラーを出さない。
- 管理画面が127.0.0.1でだけ開く。
- 未認証で状態変更APIを実行できない。
- ダッシュボードにPaper状態、ゲーム状態、オンラインプレイヤーが表示される。
- 許可外の状態遷移をDomainとAPIの両方で拒否する。
- 設定を再起動後も読める。
- 書込み途中の破損を正常版バックアップから検出・復元できる。
- UI/API/Paper AdapterがDomainロジックを重複実装していない。
- GitHub CIが関連テストとビルドを実行する。

## 3. Phase 2受入（管理ホーム・参加管理）

### 必須

- オンラインプレイヤーを管理画面で確認できる。
- ホワイトリスト状態と登録者一覧を確認できる。
- ホワイトリストON/OFF、追加、削除がPaper実状態へ反映される。
- 部分的な取得失敗を責務ごとに表示できる。

## 4. Phase 3受入（マップ管理・セットアップ）

### 必須

- 正常なJavaワールドZIPを管理画面から登録できる。
- Zip Slip、絶対パス、シンボリックリンク、上限超過を拒否する。
- 原本を直接ゲーム用にロードしない。
- 管理画面でセットアップ済みマップを選択して準備を開始できる。
- 自動抽選、直前マップ除外、次回固定は将来拡張候補であり、Phase 4必須外とする。
- 一時ワールドを生成・ロード・アンロード・削除できる。
- 無関係なワールドを削除しないことを自動テストする。
- 管理画面からセットアップを開始し、ゲーム内クリックで地点と範囲を登録できる。
- 必須項目不足のマップを有効化できない。
- 保存終了と破棄終了が正しく分かれる。
- 異常終了で残った所有一時ワールドだけを次回起動時に回収できる。

## 5. Phase 4受入（ゲーム本体）

### 必須

- 1～4人が参加でき、5人目を拒否する。
- 管理画面からオンラインプレイヤーをParticipantへ選択・除外できる。Minecraft側の参加ブロックまたは参加Zoneは将来拡張候補とする。
- ゲーム開始後の新規途中参加を拒否する。
- prepare途中失敗でもInventoryだけが消失しないよう、初期化をGameLifecycleStepのprepare / rollback / cleanup契約で扱う。
- `PREPARING`から管理画面の明示操作で`ACTIVE`を開始できる。自動開始の採否と待ち時間は未確定とする。
- ファーム内で敵、妨害、主要ダメージを無効化する。
- 初期装備とブロック単位の資源再生成が動作し、取得者本人の鉱石・農業Pointだけが増える。
- ButtonまたはInteraction等のShop操作で購入者本人のPointだけを消費し、商品を本人へ付与する。
- 敵は指定ゾーンだけに生成し、所有タグを持つ。
- 開始時参加人数と敵人数倍率がSessionへ固定され、Enemy個体性能ではなく出現数へ反映される。
- Map/ゲーム設定で決定された必要通常Core数（現在の既定値2）が候補から重複なしで選ばれる。
- 設定された必要通常Core数の破壊前に最終ゲートが開かない。
- 設定された必要通常Core数の破壊後にゲートが開き、最終Coreを攻撃できる。
- 最終コア破壊でクリアし、追加スポーンが停止する。
- 通常死亡でもInventoryを維持してファームへ戻る。具体的な復帰待ち秒数は未確定とする。
- 再接続者だけを同じGameSessionへ復帰させ、全員offlineでも即時中止しない。
- クリアと中止の両方でロビーへ戻し、ゲーム中Inventoryを全削除する。
- オフライン終了者は次回ログイン時にロビーへ戻し、ゲーム中Inventoryを削除してpending cleanupを解除する。
- 終了時に同じsessionIdの生成物だけを削除する。

## 6. Phase 5受入（妨害・管理運用完成）

### 必須

- 暗闇、浮遊、ホットバー変更、追加ウェーブを管理画面から発動できる。
- 妨害はACTIVE参加者だけに作用し、ファーム内を除外する。
- 妨害の全員/ランダム1人を選択できる。
- 全バランス値、スターターキット、個人Point Shopの商品・価格・TierをGUIから編集できる。
- ゲーム履歴とエラー追跡IDを管理画面で確認できる。
- GUIだけでマップ登録、地点設定、参加受付、開始、中止/クリア、停止まで行える。
- Windowsショートカットから一度の操作で起動し、管理画面が開く。
- 二重起動してもPaperを二重に起動しない。
- 管理画面から安全停止できる。
- ゲーム中の停止でも復元処理を先に行う。
- サーバー強制終了を模した後、次回起動で診断と安全回収ができる。
- 通常利用手順にコマンド、PowerShell、CLI操作がない。
- YouTube接続がなくても1ゲームを完走できる。

### 推奨

- 4人かつ大量Enemy出現時にTPSが配信上問題のある水準まで低下しない。
- 3種類以上のマップを連続実行して原本に変更が残らない。
- 管理画面の主要操作が一般的な1920×1080表示でスクロール過多にならない。

## 7. Phase 6受入（実マップ統合試験・v1）

Phase 1～5の必須項目を実採用マップで通し確認し、原本保護と連続実行を確認する。

## 8. Phase 7（YouTube入力アダプター）

v1受入後に別途定義する。

## 9. 手動通しテスト

1. ショートカットから起動する。
2. 管理画面でテストマップZIPを登録する。
3. セットアップを開始し、必須地点を登録する。
4. マップを有効化する。
5. 参加受付を開始し、1人参加する。
6. 準備開始し、ファームで資源取得・個人Point加算・Shop購入を確認する。
7. 攻略開始し、敵ゾーンと参加人数に応じた出現数を確認する。
8. 妨害4種を各1回発動する。
9. 1回死亡し、所持品保持と復帰を確認する。
10. 設定された必要通常Core数を破壊する。
11. Core破壊進行によりShop Tierが更新され、下位Tierを購入できないことを確認する。
12. 最終コアを破壊する。
13. ロビー帰還、ゲーム中Inventory削除、一時ワールド削除、履歴保存を確認する。
14. 2ゲーム目を開始し、原本が初期状態であることを確認する。
15. 管理画面から安全停止する。

## 10. レビュー重大度

- P0：データ/ワールド破壊、任意コマンド実行、認証回避、プレイヤー状態永久喪失。
- P1：ゲーム完走不能、状態競合、原本変更、他Entity削除、復旧不能、必須テスト欠落。
- P2：限定条件の不具合、UIの誤解、ログ不足、軽微な回帰。
- P3：表記、整理、将来改善。原則としてCodex修正回数を増やさず次回へまとめる。
