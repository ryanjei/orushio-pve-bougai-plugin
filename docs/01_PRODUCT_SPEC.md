# 製品・ゲーム仕様 v1

## 1. 目的

配信者と視聴者が最大4人で参加し、妨害を受けながら敵を突破して複数のコアを破壊する、Minecraft Java版の繰り返しプレイ可能なPvE企画を提供する。

v1の完成条件は、YouTubeに接続しなくても、管理画面から妨害を発動しながら1ゲームを開始から終了まで遊べること。YouTube連携は後から入力アダプターとして追加する。

## 2. プレイヤーと権限

- 参加人数：1～4人。配信者を含む。
- 管理者：PaperのOPかつ管理者許可リストに登録されたMinecraftユーザー。
- 観戦者：参加枠に入っていないオンラインプレイヤー。v1ではゲームワールドへ自動転送しない。
- 既定の管理者候補名：`rereyan417`。UUID解決後はUUIDで保存する。
- ゲーム開始後の新規途中参加は不可。
- ゲーム中に切断した参加者は枠を保持し、同じゲーム中に再接続した場合のみ復帰できる。

## 3. ゲーム状態

| 状態 | 説明 | 主な遷移先 |
|---|---|---|
| `IDLE` | ゲームなし | `RECRUITING`, `MAP_SETUP` |
| `RECRUITING` | 参加受付中 | `PREPARING`, `IDLE` |
| `PREPARING` | 一時ワールド生成・参加者転送・開始準備 | `ACTIVE`, `ABORTING` |
| `ACTIVE` | コア攻略中 | `CLEAR`, `ABORTING` |
| `PAUSED` | 将来の一時停止拡張用（Phase 4必須外） | `ACTIVE`, `ABORTING` |
| `CLEAR` | クリア処理・結果表示（演出時間は未確定） | `RECOVERING` |
| `ABORTING` | 中止処理 | `RECOVERING` |
| `RECOVERING` | 帰還・一時ワールド回収 | `IDLE` |
| `MAP_SETUP` | マップ地点登録中 | `IDLE` |

同時に存在できるゲームセッションまたはセットアップセッションは1つだけ。

## 4. 1ゲームの流れ

1. 管理画面でオンラインプレイヤーからParticipant（1～4人）を選択する。
2. 管理画面で使用するセットアップ済みマップを選び、「ゲーム準備開始」を押す。
3. Participant Inventoryを初期化し、原本から一時ワールドを複製・ロードしてファーム開始地点へ転送する。
4. `PREPARING`から管理画面の明示操作で`ACTIVE`を開始する。自動開始の採否と待ち時間は後続Phaseで確定する。
5. `ACTIVE`になり、設定された攻略通常Core数（現在の既定値2）だけ候補から重複なしで選ぶ。敵ゾーンを有効化する。
6. 設定された攻略通常Core数だけ破壊すると、最終エリアのゲートを開放する。
7. Participantは最終エリアへ進み、最終Coreを破壊する。
8. `CLEAR`へ遷移し、結果を表示する。演出の採否と時間は後続Phaseで確定する。
9. 全Participantをロビーへ戻し、ゲーム中Inventoryを全削除する。offline Participantは再接続時のpending cleanup対象とする。
10. OPBP所有物と一時ワールドを回収し、回収完了後に`IDLE`へ戻る。

## 5. ロビー・参加受付

- ロビーは既存の常設ワールドと位置を管理画面から登録する。
- Phase 4の正式参加方式は、管理画面からオンラインプレイヤーをParticipantへ選択・除外する方式とする。
- Participant数は1～4人とし、上限超過時は管理画面へ理由を日本語表示する。
- Minecraft側の参加ブロックまたは参加Zoneは将来拡張候補であり、Phase 4の必須受入条件に含めない。

## 6. マップ管理

### 6.1 原本と一時ワールド

- マップはJava版ワールドをZIP化し、管理画面からアップロードする。
- 原本はプラグインデータ領域に読取り専用のテンプレートとして保管する。
- ゲームでは原本を直接ロード・変更しない。
- 開始時にサーバーのワールドコンテナ直下へ、プラグイン所有の一時ワールドを生成する。
- 一時ワールド名は推測したパスではなく、内部生成IDを使用する。
- 終了時は保存せずアンロードし、所有メタデータを照合してから削除する。
- 起動時に前回異常終了の一時ワールドを検出し、安全に回収する。

### 6.2 必須登録項目

マップを「ゲームで使用可能」にするには、次がすべて必要。

- ファーム開始・死亡復帰地点
- 攻略入口地点
- 通常Core候補3個以上（攻略必要数はMap/ゲーム設定で変更可能、現在の既定値2、候補は推奨10個）
- 最終コア1個
- 最終ゲート範囲1個以上
- 敵スポーンゾーン1個以上
- 最終エリア範囲
- 最終エリアへの入口またはワープブロック
- ショップ地点1個以上

チェックポイント、追加ファーム資源ゾーン、複数ゲートは任意。

### 6.3 将来の自動マップ選択候補

Phase 4では管理画面で使用マップを明示選択する。自動選択を採用する場合の候補条件、直前マップ除外、固定指定等は後続Phaseで確定する。

## 7. ファーム・準備

### 7.1 安全性

- ファーム範囲では敵をスポーンさせない。
- 敵が侵入した場合は範囲外へ戻すか、プラグイン所有の敵なら削除する。
- PvP、敵からのダメージ、落下、溺水、炎上を無効化する。
- 妨害はファーム内のプレイヤーへ適用しない。

### 7.2 初期装備

初期装備はMap別の`gameplay-settings.yml`で編集可能な構造とする。アイテム、個数、エンチャント、壊れない設定等の具体値は該当実装Phaseで確定し、未確定値をコードへ推測で固定しない。

### 7.3 資源と個人Point

- マップに登録した資源ゾーン内で破壊された対象ブロックを記録する。
- 資源を取得したParticipant本人へ、鉱石ポイントまたは農業ポイントを加算する。他Participantの残高は変更しない。
- 資源ごとのPoint値をMap別に設定可能な構造とする。具体値は各実装Phaseで確定し、コードへ推測で固定しない。
- 再生成待ちはブロック単位で管理し、大量の個別ScheduledTaskを生成しない。
- 再生成時間はMap別に設定可能な構造とする。具体値は各実装Phaseで確定する。
- 再生成はRuntime Worldだけを対象とし、ゲーム終了後の遅延処理は破棄する。Map原本は変更しない。

### 7.4 ショップ

- Map Setupで登録したButton、Interaction等の直感的な操作地点を使用し、NPC・村人取引は使用しない。
- 操作したParticipant本人の個人Pointを確認・消費し、本人へ商品を付与する。他Participantの残高は変更しない。
- Core破壊進行に応じて同じカテゴリの購入可能Tierを上げ、上位Tier解禁後は下位Tierを購入できない。
- Shop地点は将来stable UUIDを持つ。座標配列indexを恒久的なIDにしない。
- Item FrameやDisplay Entity等を使う場合も表示Entityを正本とせず、OPBP内部状態を正本とする。生成Entityにはownershipを付ける。
- 価格、商品、使用PointカテゴリはMap別設定とし、未確定値をコードへ推測で固定しない。

## 8. PvEと敵スポーン

- 敵は登録済み直方体ゾーン内の安全な足場へスポーンする。
- プレイヤーから一定距離以内、ファーム外、空間衝突なしを確認する。
- ゾーンごとのMob構成やスポーン間隔はMap別設定可能な構造とし、具体値は実装Phaseで確定する。
- 最大同時出現数による強い上限は設けず、大量Mobをゲーム性として許容する。
- スポーン失敗時に無限再試行せず、その周期をスキップする。
- プラグインが生成した敵にsessionIdとzoneIdを付与する。
- 自然Mobや他プラグインのMobは数・削除対象に含めない。

### 8.1 人数補正

- EnemyのHP・攻撃力等の個体性能は参加人数で強化せず、原則固定する。
- 出現数は `基本スポーン数 × 敵人数倍率 × ゲーム開始時参加人数` を基礎とする。
- 小数処理は予測可能かつ0体事故を起こしにくい方式を実装Phaseで定義する。
- 開始時参加人数はSessionへ固定し、途中切断では減らさない。当面の正式サポートは1～4人とする。

## 9. コア攻略

### 9.1 通常コア

- Map/ゲーム設定で決定された攻略必要数を候補から重複なしで選ぶ。現在の既定値は2とする。
- Core HPはMap別設定可能な構造とし、具体値は実装Phaseで確定する。人数による自動補正は行わない。
- コアは表示用Entityと攻撃判定Entityで構成し、sessionId/coreIdを付ける。
- 通常の左クリック攻撃でダメージを与える。
- 使用武器の攻撃力をCore damageへ反映し、固定の1打damage上限は設けない。
- Minecraftの攻撃クールダウンを無視した連打は有効打にしない。
- 最寄りの未破壊コアHPと全体進捗をBoss Bar/Action Barへ表示する。
- 破壊時の音、Particle、Title、追加Waveは将来拡張候補とし、採否・既定値は後続Phaseで確定する。

### 9.2 最終ゲート・最終コア

- 通常コアを必要数破壊すると、登録済みゲート範囲のブロックを一時ワールド内だけ空気へ置換する。
- 最終Core HPもMap別設定可能な構造とし、未確定値をコードへ固定しない。
- 最終コア破壊で即座に敵スポーンと妨害受付を停止し、`CLEAR`へ遷移する。

## 10. 死亡・切断

- `keepInventory`をサーバー全体へ変更せず、参加者の死亡イベントで所持品・経験値を保持する。
- 通常死亡に回数制限や原則ペナルティを設けず、ファーム復帰地点へ移動する。
- 全滅によるゲームオーバーはない。
- チェックポイント登録データは将来拡張用に維持するが、Phase 4正式受入の必須機能にはしない。
- 切断でGameSessionを終了せず、全員offlineでも即時中止しない。再接続したParticipantだけを`ACTIVE`中のGameへ復帰させる。
- 最後のParticipantが切断してもゲームは自動終了しない。中止推奨警告や再接続猶予を採用する場合の具体時間は後続Phaseで確定する。

## 11. 妨害エンジン（v1は管理画面入力）

妨害の効果本体はv1で実装する。発生元は管理画面の手動ボタンと自動テストだけ。YouTubeコメント入力は後続Phaseで同じApplication Serviceへ接続する。

### 11.1 共通条件

- `ACTIVE`の参加者だけを対象にする。
- ロビー、ファーム、死亡処理中、クリア後は対象外。
- 対象が0人なら不発としてログに残す。
- 連続リクエストを安全に処理するため、既定500msの技術的な受付間隔を設ける。ゲーム上の回数上限ではない。

### 11.2 初期妨害

| ID | 効果 | 既定値 |
|---|---|---|
| `darkness` | 対象者へ暗闇 | 8秒 |
| `levitation` | 対象者へ浮遊 | 3秒・Lv1 |
| `hotbar_shuffle` | 0～8番スロットをランダム並べ替え | 全対象者 |
| `enemy_wave` | 有効な敵ゾーンに追加スポーン | 参加者ごとに3体 |

対象は「参加者全員」「ランダム1人」を管理画面で選べる。ファーム内プレイヤーは除外する。

## 12. 中止・クリア（Pauseは将来候補）

- Pause機能は将来拡張候補であり、Phase 4の必須受入条件に含めない。採用時の停止対象と状態契約は後続Phaseで確定する。
- 中止は確認ダイアログを必須とする。
- クリア・中止・例外終了のいずれも同じRecovery Serviceを通す。
- OPBPは専用PvEサーバーを前提とし、ゲーム開始時にParticipant Inventoryを初期化する。
- 終了時はゲーム中Inventoryを全削除する。通常サバイバルInventoryのSnapshot保存・復元はPhase 4正式要件に含めない。
- offline ParticipantのInventory削除はpending cleanupとして保持し、再接続時に適用する。
- 一時ワールド削除失敗はゲーム結果と分けて表示し、次回起動時に再回収する。

## 13. 結果とログ

結果として次を保存・表示する。

- sessionId、マップ、開始・終了時刻、終了理由
- 参加者UUIDと表示名
- 準備処理時間・攻略時間
- 通常コア破壊数、最終コア結果
- プレイヤー別死亡数
- 妨害種別ごとの発動数
- 管理操作、警告、エラー

ログは管理画面で最新500件を閲覧でき、永続ログは日次ローテーションする。

## 14. v1対象外

- YouTube OAuth、配信選択、コメント取得
- コメント累積難易度、キーワード判定、スーパーチャット等のマッピング
- Twitch/TikTok/Kick連携
- インターネットへの管理画面公開
- 複数ゲーム同時実行
- 複数Paperサーバー管理
- Folia対応
- 独自クライアントMODやリソースパック必須化
- マップ原本そのものをブラウザから編集する機能
