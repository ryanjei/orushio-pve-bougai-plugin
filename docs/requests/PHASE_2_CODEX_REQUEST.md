# 2. Phase 2の目的

Phase 2では、

**「配信者がMinecraftサーバーをコマンド操作せず、ブラウザ上の管理画面から基本的なサーバー参加管理を行える状態」**

を完成させます。

今回から実際に日常運用で使用できる管理画面の構築を開始します。

ただし、PvEゲーム本体や妨害システムなどにはまだ着手しません。

---

# 3. Phase 2の完成条件

以下がブラウザ上の管理画面から利用できること。

1. 管理画面を開ける
2. ホーム画面を表示できる
3. 現在オンラインのプレイヤーを確認できる
4. ホワイトリストの状態を確認できる
5. ホワイトリストをON/OFFできる
6. ホワイトリスト登録プレイヤー一覧を確認できる
7. プレイヤーをホワイトリストへ追加できる
8. プレイヤーをホワイトリストから削除できる
9. Minecraft内でのコマンド操作を原則必要としない
10. 操作失敗時に管理画面上で原因を確認できる

---

# 4. 管理画面全体方針

管理画面は今後機能が増える前提で、

**責務ごとに画面を分離する構成**

としてください。

1画面にすべての設定を詰め込む構成にはしません。

Phase 2では最低限、以下の共通UIを構築してください。

- サイドバーまたは同等のナビゲーション
- ページタイトル
- コンテンツエリア
- エラー通知
- 成功通知
- ローディング状態

UI表示言語は原則 **日本語** とします。

---

# 5. Phase 2 ホーム画面

ホーム画面では情報を過剰に表示しません。

今回必要なのは主に、

- 現在の参加者
- ホワイトリスト管理

です。

以下はホーム画面には不要です。

- ライブ配信情報
- YouTubeコメント情報
- イベントログ
- 詳細ゲームログ
- PvE進行状況
- 妨害履歴

これらは必要になったPhaseで責務別画面として追加します。

---

# 6. 現在の参加者

ホーム画面から現在Minecraftサーバーへ接続しているプレイヤーを確認できるようにしてください。

最低限表示する情報：

- Minecraftプレイヤー名

取得可能であり実装コストが過度に高くなければ、

- UUID
- 接続人数

も扱って構いません。

ただしUI上で技術情報を過剰に見せる必要はありません。

オンラインプレイヤーが0人の場合は、

「現在参加しているプレイヤーはいません」

など、正常状態であることが分かる表示にしてください。

---

# 7. ホワイトリスト状態

現在Minecraftサーバーのホワイトリストが

- ON
- OFF

どちらなのか管理画面から確認できるようにしてください。

管理画面から切り替え可能にしてください。

ON/OFF操作時はMinecraftサーバー側の実際の状態と同期してください。

単にWeb UI内部だけで状態を変更してはいけません。

---

# 8. ホワイトリスト一覧

現在ホワイトリストへ登録されているプレイヤー一覧を表示してください。

最低限：

- プレイヤー名
- 削除操作

を提供してください。

一覧が空の場合も正常に表示してください。

---

# 9. ホワイトリスト追加

管理画面からMinecraftプレイヤー名を入力し、ホワイトリストへ追加できるようにしてください。

基本UI：

`プレイヤー名入力欄`

＋

`追加ボタン`

追加成功後は一覧へ即座に反映してください。

ページ再読み込みを必須にはしないでください。

---

# 10. ホワイトリスト削除

登録済みプレイヤーを管理画面から削除できるようにしてください。

誤操作防止として、

- 確認UI
- または明確な削除操作

のいずれかを設けてください。

削除成功後は一覧へ即座に反映してください。

---

# 11. Minecraftサーバーとの整合性

Web UIだけで独自のホワイトリスト情報を持つのではなく、

**Minecraft / Paper側の実際の状態を正として扱ってください。**

可能な限りPaper APIを使用してください。

シェルコマンドや外部プロセス実行によってMinecraftコマンドを無理に叩くような構成にはしないでください。

既存Phase 1アーキテクチャと整合する方法を優先してください。

---

# 12. サーバー停止時

Minecraft側または対象機能が利用不能の場合、

管理画面がクラッシュしたり無限ロードしたりしないようにしてください。

例：

「Minecraftサーバー情報を取得できませんでした」

など、ユーザーが状況を理解できる表示を行ってください。

Phase 1で構築したエラー処理・診断・traceId等が利用可能な場合は再利用してください。

---

# 13. API

管理画面とMinecraft側との通信に必要なAPIを追加してください。

具体的なURL設計については既存Phase 1構成との整合性を優先してCodex側で設計して構いません。

ただし、

- オンラインプレイヤー取得
- whitelist状態取得
- whitelist ON/OFF
- whitelist一覧取得
- whitelist追加
- whitelist削除

の責務がコード上明確に分離されるようにしてください。

既存OpenAPI基盤がある場合は更新してください。

---

# 14. UI/UX

今回の管理画面は、

**ゲームサーバー管理ツールではあるが、一般ユーザーでも扱えるUI**

を目指します。

そのため、

- JSONを直接表示しない
- 技術用語を必要以上に露出させない
- コマンド入力欄を作らない
- PowerShell操作を要求しない
- CLI操作を日常運用として要求しない

こと。

日常運用はブラウザGUIのみで完結する方向にしてください。
